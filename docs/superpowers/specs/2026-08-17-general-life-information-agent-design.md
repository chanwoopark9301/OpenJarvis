# OpenJarvis 범용 생활 정보 처리 설계

## 배경

현재 `jarvis chat`은 인터넷 검색이 성공하면 질문 종류와 관계없이 모든 결과를
여행 일정 생성기와 일정 검사기로 보낸다. 이 때문에 날씨 질문도 방문 일정으로
출력되고, 일정에 맞지 않는 검색 결과는 안전 안내로 폐기된다. 생활 분야마다
날씨, 운동, 제품, 맛집 전용 모델을 추가하는 방식은 새로운 요청이 생길 때마다
코드를 바꿔야 하므로 개인 비서의 범용성에도 맞지 않는다.

## 목표

- 하나의 범용 계획기가 대화, 추가 질문, 정보 검색, 도구 행동을 구분한다.
- 날씨, 운동, 제품, 지역 정보, 뉴스처럼 처음 보는 생활 정보 요청도 같은 검색
  흐름으로 처리한다.
- 답변 모양은 분야가 아니라 사용자의 목적에 따라 짧은 답, 목록, 비교, 순서
  안내 중 하나로 고른다.
- 필수 정보가 없으면 검색어를 꾸며내지 않고 한 번에 이해되는 질문을 한다.
- 검색으로 얻은 사실은 출처 자료와 연결하고, 근거 없는 사실만 제거한다.
- 개인 대화와 기억은 내 컴퓨터 안에서만 계획에 사용하고 외부 검색어에는 필요한
  공개 정보만 포함한다.
- 작은 로컬 모델이 자료 형식을 조금 어겨도 한 번 복구한 뒤 안전하게 실패한다.
- 기존의 평범한 말동무 대화와 개인 기억 연결은 그대로 유지한다.

## 이번 범위

- 일반 대화와 검색 요청 구분
- 최근 대화를 참고한 이어지는 요청 이해
- 필수 정보가 빠진 검색 요청에 대한 추가 질문
- 공개 검색어 최대 세 개 생성
- 검색 결과 선별과 번호 부여
- 근거가 연결된 범용 답변 생성, 검사, 자연스러운 출력
- 검색 실패와 자료 형식 오류의 안전한 처리
- 기존 여행 일정 요청을 범용 순서 안내로 처리

## 범위 밖

- 브라우저를 열고 누르거나 입력하는 작업
- 장바구니 담기, 주문, 결제, 예약, 전송
- 사용자의 확인 없이 외부 상태를 바꾸는 작업
- 지도 이동 시간의 정밀 계산
- 끝없는 검색 반복

도구 행동은 계획 자료에서 별도 종류로 남긴다. 현재는 실행 도구가 연결되지
않았다고 솔직하게 설명하며, 다음 단계에서 브라우저 도구를 연결해도 계획기와
답변기의 구조를 다시 바꾸지 않도록 한다.

## 핵심 원칙

### 분야가 아니라 능력으로 나누기

처리 종류는 날씨나 운동 같은 분야 이름이 아니라 다음 네 가지 능력이다.

- `chat`: 검색이 필요 없는 대화나 설명
- `clarify`: 결과를 만들기 위한 필수 정보가 빠져 있어 사용자에게 질문
- `search`: 현재 또는 외부 공개 정보가 필요해 인터넷 검색
- `action`: 외부 상태 변경이 필요한 요청이며 현재 실행할 수 없음

### 규칙은 짧고 공통적으로 유지하기

하나의 거대한 분야별 규칙 모음 대신 모든 생활 요청에 적용되는 규칙만 둔다.

- 사용자의 실제 목적을 보존한다.
- 필수 정보가 없으면 묻는다.
- 공개 정보만 검색한다.
- 사실은 근거와 연결한다.
- 조언과 추측을 사실처럼 쓰지 않는다.
- 지원하지 않는 행동을 했다고 말하지 않는다.

## 구조

### 1. 빠른 통과 판정과 범용 요청 계획기

명백한 인사, 감정 대화, 말동무 요청은 현재의 가벼운 판정으로 바로 기존 대화
경로에 보낸다. 검색, 비교, 추천, 확인, 계획, 외부 행동처럼 추가 작업 가능성이
있는 요청만 범용 계획기를 호출한다. 이 빠른 통과 판정은 분야를 분류하지 않고
“추가 작업이 필요한가”만 판단하므로 새로운 생활 분야가 생겨도 규칙을 추가하지
않는다.

계획기가 추가 질문을 한 경우에는 그 대답을 기다리는 상태를 대화 안에 남긴다.
다음 사용자 말은 짧은 지역명이나 제품명뿐이어도 범용 계획기로 보내고, 한 번
처리한 뒤 대기 상태를 지운다. 따라서 추가 질문 직후의 짧은 답을 일반 잡담으로
오해하지 않으며, 검색이 끝난 뒤의 “고마워”까지 불필요하게 계획하지 않는다.

내 컴퓨터의 모델은 현재 사용자 말과 필요한 만큼의 최근 대화를 읽고 다음 자료를
만든다.

```json
{
  "mode": "search",
  "goal": "과천시의 오늘 날씨를 간단히 알려주기",
  "clarifying_question": "",
  "response_style": "direct",
  "requirements": [
    {
      "id": "R1",
      "query": "경기도 과천시 오늘 날씨 현재 기온 강수",
      "required_terms": ["과천시", "날씨"]
    }
  ]
}
```

허용되는 `response_style`은 다음 네 가지뿐이다.

- `direct`: 짧은 질문과 단일 결과
- `list`: 여러 후보나 항목
- `comparison`: 제품이나 선택지 비교
- `steps`: 일정, 방법, 절차처럼 순서가 중요한 요청

계획기는 최대 세 개의 검색 항목만 만든다. 검색 항목은 공개 장소, 제품, 날짜,
운동 종류 같은 검색에 필요한 정보만 담는다. 사람 이름, 관계, 감정, 집 세부 정보,
전화번호, 전자우편 주소는 기존 차단 규칙을 유지한다.

### 2. 필수 정보 판단과 추가 질문

계획기는 답을 만들 수 없는 핵심 정보가 빠졌을 때 `clarify`를 선택한다.

- “오늘 날씨 검색해 줘”에서 현재 지역을 알 수 없으면 지역을 묻는다.
- “운동법 검색해 줘”는 일반 운동법 목록으로 답할 수 있으므로 반드시 질문하지
  않는다. 다만 사용자가 부상 회복이나 특정 기록 향상처럼 좁은 결과를 요구했는데
  필요한 조건이 없으면 한 가지 질문을 한다.
- “이 둘 중 뭐가 나아?”처럼 최근 대화가 있어야 이해되는 요청은 최근 대화에서
  대상을 찾는다.

추가 질문은 한 번에 하나만 하고, 이미 현재 말이나 최근 대화에 있는 정보를 다시
묻지 않는다.

### 3. 범용 검색 실행기

`search`일 때만 계획의 공개 검색어를 외부 검색 도구에 전달한다. 검색 결과는
기존처럼 `S1`, `S2` 번호를 가진 근거 자료로 바꾼다.

- 제목
- 주소
- 짧은 설명
- 검색 항목 번호
- 자료 종류

검색 결과는 요청 지역, 제품명, 주제 같은 핵심 단어가 맞아야 통과한다. 이름 없는
소셜 계정, 다른 도시, 검색어를 되풀이한 설명뿐인 자료는 제외한다. 부족한 검색
항목만 공개 정보로 한 번 다시 검색하고 그 뒤에는 반복하지 않는다.

### 4. 범용 근거 답변기

검색 뒤 내 컴퓨터의 모델은 일정 전용 자료가 아니라 다음 범용 답변 자료를 만든다.

```json
{
  "lead": "과천시의 현재 날씨를 확인했어.",
  "blocks": [
    {
      "kind": "fact",
      "text": "현재 기온은 24도야.",
      "supports": [
        {"source_id": "S1", "excerpt": "현재 기온 24도"}
      ]
    },
    {
      "kind": "advice",
      "text": "늦게 나간다면 얇은 겉옷 정도면 충분해 보여.",
      "supports": []
    }
  ],
  "follow_up": ""
}
```

허용되는 글 조각 종류는 다음 세 가지다.

- `fact`: 검색 자료로 확인할 수 있는 사실
- `advice`: 사용자의 목적에 맞춘 일반 조언
- `uncertain`: 자료가 부족하거나 서로 달라 확인이 필요한 내용

`fact`는 근거 번호와 근거 자료에서 그대로 가져온 짧은 뒷받침 문구를 반드시
가진다. `advice`는 근거가 없어도 되지만 새로운 장소, 가격, 시간, 수치처럼
검증 가능한 사실을 만들 수 없다. `uncertain`은 무엇을 확인하지 못했는지
분명하게 말한다.

### 5. 범용 근거 검사기

검사기는 분야를 알 필요 없이 자료 연결만 확인한다.

- 근거 번호가 실제 검색 결과에 존재하는가
- 뒷받침 문구가 해당 결과의 제목이나 짧은 설명에 실제로 포함되는가
- 답변의 숫자, 날짜, 가격, 시간, 주소가 뒷받침 문구에도 나타나는가
- 장소와 제품의 핵심 이름이 뒷받침 문구에도 나타나는가
- 조언에 새로운 검증 가능 사실이 섞이지 않았는가

검사를 통과하지 못한 사실 조각만 제거하거나 `uncertain`으로 낮춘다. 하나의
잘못된 조각 때문에 확인된 답변 전체를 버리지 않는다.

### 6. 자연스러운 출력기

출력기는 `response_style`에 따라 같은 검증 자료를 읽기 편하게 배치한다.

- `direct`: 짧은 문단
- `list`: 글머리표 목록
- `comparison`: 같은 기준으로 나란히 비교
- `steps`: 순서가 보이는 단계나 시간 흐름

분야별 고정 문구는 두지 않는다. 날씨에 “방문 전 확인”을 붙이거나 일반 검색을
무조건 일정으로 만드는 일이 없어야 한다. 사용자가 금지한 문자와 표현은 최종
출력에서도 제거한다. 출처는 실제로 사용한 것만 답변 끝에 표시한다.

## 대화 흐름

### 지역 없는 날씨

```text
사용자: 오늘 날씨 검색해 볼래?
계획기: clarify
답변: 어느 지역의 날씨를 볼까?
```

### 지역이 있는 날씨

```text
사용자: 경기도 과천시의 오늘 날씨를 검색해 봐.
계획기: search, direct
검색: 과천시 오늘 날씨
답변기: 기온, 비 가능성, 바람처럼 자료가 있는 사실만 작성
출력기: 짧은 날씨 답변과 사용한 출처 표시
```

### 운동 정보

```text
사용자: 집에서 할 수 있는 허리 운동법을 검색해 줘.
계획기: search, steps
검색: 믿을 만한 허리 운동 안내
답변기: 순서와 주의점을 근거에 연결
출력기: 짧은 단계 목록
```

### 제품 비교

```text
사용자: 무설탕 탄산음료 세 개를 찾아서 비교해 줘.
계획기: search, comparison
검색: 제품별 공개 정보
답변기: 가격과 용량은 근거가 있을 때만 포함
출력기: 같은 기준의 비교와 출처
```

### 여행 계획

```text
사용자: 테미오래 다음에 한식 식당과 소품샵을 가는 일정을 짜 줘.
계획기: search, steps
검색: 장소별 공개 정보
답변기: 확인된 사실과 일반적인 이동 순서를 분리
출력기: 순서 안내
```

### 지원하지 않는 행동

```text
사용자: 쿠팡에서 음료수를 주문해 줘.
계획기: action
답변: 아직 웹사이트를 직접 조작하는 기능은 연결되지 않았다고 설명
```

## 작은 모델 오류 처리

- 계획 자료가 올바르지 않으면 같은 내용을 한 번만 자료 형식으로 복구한다.
- 복구에도 실패하면 외부 검색을 하지 않고 “요청을 이해하지 못했어. 찾고 싶은
  내용을 한 문장으로 다시 말해 줄래?”라고 묻는다.
- 검색 결과가 하나도 없으면 찾지 못했다고 말하고 장소나 수치를 만들지 않는다.
- 일부 검색만 성공하면 성공한 근거로 답하고 빠진 부분만 `uncertain`으로 남긴다.
- 답변 자료가 올바르지 않으면 한 번만 복구한다.
- 두 번째도 실패하면 사용한 검색어와 관련 출처를 보여주는 현재의 안전 안내로
  돌아간다.
- 모델이 `action`을 실제 완료했다고 주장해도 실행 기록이 없으면 완료 문구를
  출력하지 않는다.

## 개인정보 경계

- 계획과 추가 질문 판단은 내 컴퓨터의 모델만 수행한다.
- 최근 대화와 개인 기억은 계획기에만 전달하고 외부 검색 도구에는 보내지 않는다.
- 외부 검색에는 검사된 공개 검색어만 전달한다.
- 기존의 관계, 연락처, 전자우편, 집 정보 차단을 유지한다.
- 검색 결과는 지시가 아닌 신뢰하지 않는 참고 자료로 취급한다.
- 검색 결과 안의 명령문은 실행하지 않는다.

## 기존 기능과의 관계

- 기존의 명시적 검색과 최신 정보 감지는 분야 분류기가 아니라 범용 계획기를
  호출할지 정하는 빠른 통과 판정으로 축소한다.
- 일정 전용 생성기와 검사기는 `jarvis chat`의 공통 검색 경로에서 제거한다.
- 일정 요청도 범용 답변기의 `steps` 출력으로 처리한다.
- 개인 기억 저장과 대화 기록 흐름은 바꾸지 않는다.
- 검색하지 않는 평범한 대화는 추가 계획 호출 없이 현재 경로를 유지한다.

## 검사 계획

### 요청 처리

- “안녕?”은 검색과 계획 추가 호출 없이 대화한다.
- “검색해 줘”, “인터넷에서 찾아 줘”는 분야와 관계없이 검색한다.
- 최신 날씨, 가격, 운영시간처럼 바뀌는 정보는 검색한다.
- 외부 행동 요청은 실행했다고 말하지 않는다.

### 추가 질문과 이어지는 대화

- 지역 없는 오늘 날씨는 지역을 한 번 묻는다.
- 과천시가 포함된 날씨 요청은 다시 지역을 묻지 않는다.
- 이전 말에 지역이나 비교 대상이 있으면 이어지는 요청에 사용한다.
- 이미 제공한 정보를 반복해서 묻지 않는다.

### 범용 출력

- 날씨는 일정 형식이나 방문 문구로 출력되지 않는다.
- 운동법은 순서 안내로 출력된다.
- 제품 비교는 같은 기준의 비교로 출력된다.
- 여행 요청은 순서 안내를 유지한다.
- 처음 보는 생활 주제도 일정 전용 문구 없이 답한다.

### 근거와 안전

- 존재하지 않는 근거 번호는 제거된다.
- 근거에 없는 숫자, 가격, 시간, 주소는 제거된다.
- 근거 문구가 실제 검색 자료에 없으면 사실 조각이 통과하지 않는다.
- 한 조각이 잘못되어도 확인된 다른 조각은 남는다.
- 다른 지역이나 무관한 소셜 자료는 답변 근거로 사용되지 않는다.
- 개인적인 원문은 외부 검색 도구 입력에 나타나지 않는다.

### 오류와 회귀

- 계획 자료와 답변 자료는 각각 한 번만 복구한다.
- 검색이 모두 실패하면 모델 기억으로 최신 사실을 꾸미지 않는다.
- 평범한 대화, 개인 기억 저장, 대화 종료가 이전처럼 작동한다.
- 전체 저장소 검사를 통과한다.

## 완료 기준

- 과천시 날씨 질문에 일정이 아닌 짧은 날씨 답변이 나온다.
- 지역 없는 날씨 질문에는 검색 실패 안내가 아니라 지역 질문이 나온다.
- 운동, 제품 비교, 지역 추천, 뉴스, 여행 계획이 같은 범용 흐름을 사용한다.
- 처음 보는 생활 정보 요청에 새 전용 모델이나 새 분야별 처리기를 만들 필요가
  없다.
- 근거 없는 사실과 지원하지 않는 행동 완료 주장이 최종 답변에 나오지 않는다.
- 실제 `jarvis chat`에서 대표 요청과 이어지는 대화를 확인한다.
- 관련 검사와 전체 저장소 검사를 통과한 뒤 원격 기능 가지에 푸시한다.
