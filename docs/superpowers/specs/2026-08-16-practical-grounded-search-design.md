# OpenJarvis Practical Grounded Search Design

## 배경

현재 자동 검색은 검색 자체에는 성공해도 최종 답변에 확보한 주소가 글자 그대로
들어 있지 않으면 답변 전체를 폐기한다. 이 방식은 꾸며낸 장소를 차단하지만,
검색 자료로 만들 수 있는 실용적인 일정까지 함께 버린다. 검색 결과도 짧은 설명
위주라 한 번의 검색만으로는 운영 정보, 식당, 상점 지역을 모두 채우지 못할 수
있다.

## 목표

- 최신 정보가 필요한 요청은 먼저 검색한다.
- 부족한 정보만 검색어를 바꿔 한 번 더 찾는다.
- 출처 주소 복사 여부가 아니라 출처 번호 연결로 근거를 검사한다.
- 근거 없는 항목만 제거하고 확인된 일정은 자연스럽게 보여준다.
- 일부 정보가 부족하면 해당 부분에만 방문 전 확인 표시를 붙인다.
- 개인적인 배경은 외부 검색어에 넣지 않는다.

## 범위 밖

- 지도 이동 시간의 정밀 계산
- 예약이나 전화 걸기
- 검색 결과에 없는 업체를 모델 기억만으로 추천하기
- 검색을 끝없이 반복하기
- 외부 모델에 개인 대화 원문을 보내기

## 권장 구조

### 1. 요청 항목 나누기

검색어 생성기는 사용자 요청을 최대 세 가지 공개 정보 항목으로 나눈다. 대전
일정 예시에서는 다음 세 항목이 된다.

- 이름이 지정된 방문 장소의 공식 운영 정보와 접근 방법
- 주변 한식 장소
- 여러 소품샵을 함께 둘러볼 수 있는 지역이나 묶음

각 항목은 고유한 번호와 검색 목적을 가진다. 관계, 선물, 감정 같은 개인 배경은
항목과 검색어에서 제외한다.

### 2. 근거 자료 만들기

검색 결과는 주소 문자열 모음이 아니라 다음 필드를 가진 근거 자료로 정리한다.

- 근거 번호: `S1`, `S2` 형식
- 검색 항목 번호
- 제목
- 주소
- 짧은 설명
- 자료 종류: 공식, 업체, 모음, 개인 후기, 기타

이름이 지정된 장소의 운영 정보에는 공식 자료를 우선한다. 식당과 상점은 서로
다른 자료가 같은 장소를 가리킬 때 더 높은 확인 정도를 부여할 수 있다.

### 3. 부족한 항목만 한 번 더 검색하기

첫 검색 뒤 항목별 충족 여부를 판정한다.

- 운영 정보: 이름이 지정된 장소와 관련된 공식 또는 직접 자료가 있는가
- 한식 장소: 대전과 요청 지역에 맞는 개별 장소 자료가 있는가
- 소품샵 지역: 같은 지역의 여러 상점 또는 상점 모음을 뒷받침하는 자료가 있는가

충족되지 않은 항목만 검색어를 바꿔 한 번 더 검색한다. 두 번째 검색에서도
근거가 부족하면 더 반복하지 않고 그 항목을 확인 필요로 남긴다.
두 번째 검색어 생성에는 공개 정보 항목과 부족한 조건만 전달하고 개인 대화
원문은 다시 사용하지 않는다.

### 4. 구조화된 일정 만들기

내 컴퓨터의 모델은 바로 완성 문장을 쓰지 않고 일정 항목 목록을 만든다. 각
항목은 다음 정보를 담는다.

- 시간대
- 제목
- 설명
- 장소 이름
- 근거 번호 목록
- 확인 정도: `확인`, `일부 확인`, `확인 필요`
- 방문 전 확인할 내용

장소 이름, 주소, 운영시간 같은 검증 가능한 사실을 쓰려면 하나 이상의 유효한
근거 번호가 필요하다. 이동 순서나 여유 시간처럼 사용자가 원하는 계획 구성은
근거 없이도 제안할 수 있지만 사실처럼 단정하지 않는다.
일정 항목 목록은 엄격한 자료 형식으로 받고, 임의의 설명 문장은 허용하지 않는다.

### 5. 항목별 검사와 자연스러운 출력

검사기는 일정 전체를 한꺼번에 통과시키거나 폐기하지 않는다.

- 유효한 근거 번호가 있는 사실 항목은 유지한다.
- 업체명은 연결된 근거의 제목이나 짧은 설명에 같은 이름이 있을 때만 유지한다.
- 주소와 운영시간은 연결된 근거에 같은 값이 나타날 때만 확정 정보로 유지한다.
- 근거가 일부만 맞으면 확인 정도를 `일부 확인`으로 낮추고 확인 문구를 붙인다.
- 검색 자료에 없는 업체명, 주소, 전화번호, 운영시간은 해당 항목에서 제거한다.
- 근거가 없는 항목은 일반적인 동선 제안으로 바꾸거나 `확인 필요`로 표시한다.
- 유효한 근거 번호는 최종 답변 끝의 실제 주소 목록으로 바꾼다.

사용자는 먼저 시간 순서의 일정안을 보고, 각 항목 뒤에서 짧은 확인 상태를 본다.
출처 목록은 답변 끝에 모아 읽기 흐름을 방해하지 않게 한다.

## 실패 처리

- 검색어 생성 실패: 현재의 고정된 검색 실패 안내를 표시한다.
- 모든 검색 실패: 최종 답변 모델을 호출하지 않는다.
- 일부 항목만 검색 실패: 확인된 항목으로 일정을 만들고 실패한 부분만 표시한다.
- 일정 자료 형식 오류: 같은 근거로 형식 복구를 한 번 시도한다.
- 형식 복구도 실패: 검색어와 출처만 보여주는 안전 안내로 돌아간다.
- 유효한 근거가 하나도 없음: 장소나 시간을 꾸미지 않고 검색 실패로 처리한다.

## 개인정보 경계

- 검색 여부 판정은 내 컴퓨터에서 한다.
- 검색어 생성도 내 컴퓨터의 모델만 사용한다.
- 외부 검색에는 정리된 공개 검색어만 전달한다.
- 관계, 이름, 전화번호, 전자우편 주소, 집 정보는 기존 차단 규칙을 유지한다.
- 검색 결과는 지시가 아닌 신뢰하지 않는 참고 자료로 취급한다.

## 검사 계획

- 충분한 세 항목이 한 번의 검색으로 일정안에 연결된다.
- 한 항목만 부족하면 그 항목만 두 번째 검색을 한다.
- 두 번째 검색 뒤에도 부족한 항목은 확인 필요로 표시된다.
- 모델이 주소를 본문에 복사하지 않아도 유효한 근거 번호가 있으면 통과한다.
- 존재하지 않는 근거 번호가 붙은 업체는 제거된다.
- 근거 없는 업체 하나 때문에 근거 있는 일정 전체가 폐기되지 않는다.
- 최종 출처 번호가 실제 주소로 정확히 바뀐다.
- 평범한 대화는 검색과 추가 모델 호출을 하지 않는다.
- 개인적인 원문이 외부 검색 도구에 전달되지 않는다.

## 완료 기준

대전 일정 예시에서 다음 결과를 만족해야 한다.

- 테미오래 운영 정보, 한식 장소, 소품샵 지역을 따로 검색한다.
- 부족한 항목만 최대 한 번 다시 검색한다.
- 확인된 정보로 시간 순서의 일정안을 출력한다.
- 확인되지 않은 부분은 숨기거나 방문 전 확인으로 표시한다.
- 답변 전체를 주소 복사 여부만으로 폐기하지 않는다.
- 최종 답변의 출처 번호와 실제 주소가 일치한다.
