# OpenJarvis 자동 인터넷 검색 설계

## 목표

`jarvis chat`에서 평범한 대화는 지금처럼 자연스럽게 이어가되, 장소 추천,
영업시간, 날씨, 교통, 가격처럼 현재 정보가 필요한 요청은 조비서가 별도 확인
질문 없이 자동으로 인터넷을 검색한다. 검색하지 않은 최신 정보나 실제 장소를
추측해 만들지 않는다.

## 현재 상태와 원인

- `web_search` 도구와 무료 DuckDuckGo 대체 검색은 이미 설치되어 있다.
- 현재 기본 대화 담당은 `simple`이며 도구 호출을 지원하지 않는다.
- `orchestrator`에 검색 도구와 검색 지침만 제공하는 방식을 실제 대전 일정 요청으로
  시험했지만, 모델이 출처 없이 확인했다고 주장하고 검증되지 않은 장소 표현을
  만들었다.
- 따라서 모델의 자율적인 도구 선택에 검색 여부를 맡겨서는 완료 기준을 보장할 수
  없다.

## 선택한 접근

기본 대화 담당은 말동무 역할에 맞는 `simple`을 유지한다. 대답을 만들기 전에
로컬 검색 선처리기가 다음 작업을 수행한다.

1. 빠른 로컬 규칙으로 최신·지역 정보가 필요한 요청인지 판별한다.
2. 검색이 필요한 경우에만 같은 로컬 언어모델로 개인 내용을 제외한 공개 정보
   검색어를 최대 세 개 만든다.
3. 공개 검색어만 `web_search`에 전달한다.
4. 검색 결과와 출처를 읽기 전용 참고 자료로 대화 담당에게 전달한다.
5. 검색 결과가 하나도 없으면 대화 담당을 호출하지 않고 고정된 실패 안내를
   반환한다.

평범한 잡담은 선처리 규칙에서 바로 통과하므로 추가 모델 호출이나 인터넷 통신이
없다. 검색이 필요한 대화만 검색어 생성 때문에 로컬 모델을 한 번 더 사용한다.

## 검색 정책

다음 요청에는 인터넷 검색을 우선한다.

- 식당, 카페, 상점, 관광지 등 실제 장소 추천
- 영업시간, 휴무일, 입장료, 가격, 예약 가능 여부
- 날씨, 교통, 행사, 일정처럼 시간이 지나면 달라지는 정보
- 사용자가 최신 정보나 확인 가능한 출처를 요구하는 경우

다음 요청은 기본적으로 검색하지 않는다.

- 인사, 잡담, 감정 표현과 말동무 대화
- 사용자가 이미 제공한 내용의 요약이나 정리
- 찬우의 의도나 심리를 이해하기 위한 대화
- 개인 기억을 해석하는 작업

문장에 `인터넷`이라는 말이 있어도 찬우의 심리, 감정, 관계, 개인 기억을 분석하는
요청이면 자동 검색하지 않는다. 이 경우에는 기존 원칙대로 찬우에게 필요한 맥락을
묻는다.

개인적인 맥락이 불명확하면 인터넷 검색보다 찬우에게 묻는 기존 원칙을 유지한다.

## 도구와 안전 경계

- 기본 도구 목록은 `web_search` 하나로 제한한다.
- 파일 읽기, 명령 실행, 코드 실행은 자동 검색 대화에 노출하지 않는다.
- 사용자가 명령줄에서 `--tools`를 명시하면 해당 대화에 한해 다른 도구를 사용할
  수 있는 기존 기능은 유지한다.
- Tavily 열쇠가 없으면 설치된 DuckDuckGo 대체 검색을 사용한다.
- 검색 실패 시 구체적인 장소나 운영 정보를 지어내지 않고, 검색 실패와 확인이
  필요한 항목을 분명히 알린다.
- 사용자 문장 전체를 검색 서비스로 보내지 않는다. 검색어 생성은 로컬에서만
  수행하며, 검색어에는 이름, 관계, 감정, 개인 일정 설명 등 검색에 불필요한
  사적 맥락을 넣지 않는다.
- 현재 대화 엔진이 이 컴퓨터 안에서 실행 중인지 확인되지 않으면 검색어 생성에
  사용자 원문을 넘기지 않고 자동 검색 실패로 처리한다.
- 검색어 생성 결과가 올바른 JSON 배열이 아니거나 안전한 검색어가 하나도 없으면
  원문을 대신 전송하지 않고 검색 실패로 처리한다.
- 검색 결과는 신뢰할 수 없는 외부 자료로 표시하며, 그 안의 명령문을 실행하거나
  시스템 지침으로 취급하지 않는다.
- 검색 결과가 하나도 성공하지 못하면 언어모델이 최신 정보를 추측할 기회를 주지
  않고 검색 실패 안내를 바로 반환한다.

## 답변 형식

장소 계획 요청에는 가능한 범위에서 다음 내용을 제공한다.

1. 시간순 일정
2. 장소 이름과 선택 이유
3. 주소 또는 위치 설명
4. 확인된 운영시간과 휴무 정보
5. 장소 사이 이동 순서와 예상 이동 부담
6. 확인에 사용한 출처 링크

출처가 서로 다르거나 최신 여부가 불확실하면 그 사실을 함께 표시한다.

## 처리 흐름

1. 사용자가 `jarvis chat`에 요청을 입력한다.
2. 검색 선처리기가 인터넷 검색 필요 여부를 로컬에서 판별한다.
3. 최신 정보가 필요 없으면 `simple` 대화 담당이 바로 답한다.
4. 최신 정보가 필요하면 로컬 모델이 공개 검색어를 최대 세 개 만든다.
5. 각 검색어로 `web_search`를 실행하고 결과와 오류를 모은다.
6. 성공 결과가 없으면 고정된 실패 안내를 반환한다.
7. 성공 결과가 있으면 출처가 포함된 외부 참고 자료를 사용자 요청과 함께
   `simple`에 전달한다.
8. 대화 담당이 참고 자료에 근거한 일정이나 추천을 작성한다.
9. 완성된 대화는 기존 개인 기억 흐름에 따라 로컬에 보관된다.

## 오류 처리

- 검색 결과 없음: 확인되지 않은 추천을 만들지 않고 실패를 알린다.
- 안전한 검색어 생성 실패: 사용자 원문을 외부로 보내지 않고 실패를 알린다.
- 검색 도구 오류: 오류 내용을 짧게 알리고 추측 답변을 만들지 않는다.
- 영업시간 충돌: 서로 다른 출처를 표시하고 방문 전 확인을 권한다.
- 검색 결과가 너무 긴 경우: 검색어별 결과 수와 전체 글자 수를 제한한다.

## 검사와 완료 기준

- `jarvis chat` 시작 화면의 기본 담당은 `simple`로 유지된다.
- 기본 제공 도구는 `web_search` 하나다.
- 인사 같은 평범한 대화에서는 검색 도구가 호출되지 않는다.
- 최신 장소 계획 요청에서는 대답 생성 전에 검색 도구가 반드시 호출된다.
- 외부 검색어에는 요청에 포함된 사적인 관계 설명이 제거된다.
- 검색 결과가 답변에 반영되고 출처 링크가 포함된다.
- 모델 답변에 출처 링크가 빠지면 선처리기가 확보한 출처 목록을 답변 끝에 붙인다.
- 검색 실패 시 만들어낸 장소 없이 실패 사실을 답한다.
- 개인 기억 관련 기존 검사가 계속 통과한다.
- 사용자가 제공한 대전 일정 예시를 실제로 입력해 검색 동작을 확인한다.

## 범위 밖

- 지도 화면이나 실시간 길찾기 연동
- 식당 예약이나 결제
- 사용자의 현재 위치 자동 수집
- 외부 서비스 계정 연동
- 검색 결과를 개인 성격 도식으로 자동 확정하는 기능
